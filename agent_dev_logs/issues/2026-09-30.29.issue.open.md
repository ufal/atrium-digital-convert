Agreed at the AMČR meeting on 30 September: this repository becomes the born-digital stage of the pipeline: **born-digital documents in, the `atrium_document` record out**. Its LLM keyword code moves to `ufal/atrium-keyword-extractor` (ufal/atrium-nlp-enrich#40).

**What the converter produces.** The "JSON of per-page blocks" is the record that `digital-convert` already writes: pages with their text-layer check and `needs_ocr` flag, lines with boxes, blocks (`group_id`) and regions, and tables. The service (`api-digital`, endpoint `/reformat`) is #28.

**Describing pages.** The converter does not call page-classification or ocr-postprocess itself. In the AMČR pipeline, Temporal chains the stages, so page categories and line quality come from the next two steps. The converter provides what the route step needs: pages flagged for OCR, and a registered refusal (`ocr_text_layer`) for PDFs whose text layer is an earlier OCR run.

**Scope**
- move the LLM and vocabulary code, with its history, to keyword-extractor (after its last release here)
- rename the repository and update its identity (service id, CITATION, README, images, Pages)
- update the hub's references (lists, E2E, docs site), the ARUP-CAS fork, the SSHOMP records and the Galaxy wrapper
- keep the converter's program id, `digital-convert`, so no record changes

**Acceptance**
- [ ] the repository is renamed, and the old URL redirects
- [ ] there is no LLM code in the tree or in any image of this repository
- [ ] records written after the move have the same shape as 0.8.0's
- [ ] the hub's digital E2E is green against the renamed images

**To decide**
- the spelling, `convertor` or `converter`: GHCR package names cannot be renamed later
- should `/reformat` return the record, with the Markdown only on request?
- 1.0.0 for the first release after the LLM endpoints are gone?
