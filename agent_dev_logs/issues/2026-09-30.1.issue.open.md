For now: the input PDF is turned into JSON of per-page blocks with extracted information 

Potential calls to the ocr-postprocess and page-classification repo tools to describe pages for further processing steps 


Agreed at the AMČR meeting on 30 September: this repository becomes the born-digital stage of the pipeline: **born-digital documents in, the `atrium_document` record out**. Its LLM keyword code moves to `ufal/atrium-keyword-extractor` (ufal/atrium-keyword-extract#1).

**What the converter produces.** The "JSON of per-page blocks" is the record that `digital-convert` already writes: pages with their text-layer check and `needs_ocr` flag, lines with boxes, blocks (`group_id`) and regions, and tables. The service (`api-digital`, endpoint `/reformat`) is ufal/atrium-nlp-enrich#28.

**Describing pages.** The converter does not call page-classification or ocr-postprocess itself. In the AMČR pipeline, Temporal chains the stages, so page categories and line quality come from the next two steps. The converter provides what the route step needs: pages flagged for OCR, and a registered refusal (`ocr_text_layer`) for PDFs whose text layer is an earlier OCR run.

**Scope**
- move the LLM and vocabulary code, with its history, to keyword-extractor (after its last release here)
- rename the repository and update its identity (service id, CITATION, README, images, Pages)
- update the hub's references (lists, E2E, docs site), the ARUP-CAS fork, the SSHOMP records and the Galaxy wrapper
- keep the converter's program id, `digital-convert`, so no record changes

**Acceptance**
- [ ] the repository is renamed, and the old URL redirects
- [x] there is no LLM code in the tree or in any image of this repository
- [x] records written after the move have the same shape as 0.8.0's
- [x] the hub's digital E2E is green against the renamed images

**To decide**
- the spelling, `convertor` or `converter`: GHCR package names cannot be renamed later
- should `/reformat` return the record, with the Markdown only on request?
- 1.0.0 for the first release after the LLM endpoints are gone?

Plan: `agent_dev_logs/plans/29.plan.md` (design options in §A).

**What changed**
- **The service** is now the born-digital stage. `service/api.py` serves:
  - `POST /reformat` (the AMČR route; calls no other service);
  - `POST /describe` (an optional per-page assessment, see #2);
  - the common `/info`, `/health` and `/ready`.

  The service id is `atrium-digital-convert`, and the spec declares the rename from `atrium-llm-enrich`. The program id in records stays `digital-convert`.
- **The images** are `ghcr.io/ufal/atrium-digital-convert-api` (production) and `-digital` (CLI). The `remote` and `llm` targets are gone. `digital-docling` stays a local, unpublished build.
- **Metadata:** `para_config.txt` (`digital-convert`, `v1.1.0-beta`), `CITATION.cff`, `.github/production-image.json` (checked with the hub's closure tool: 15 core, 8 shared, 3 vendored), compose, `.env.example`, the docker/security/para-drift/dependabot workflows, README, CONTRIBUTING, `service/README.md`.
- **The LLM/vocabulary code left the tree in 20dabd8** (76 files): the clients and engine, prompts, the vocabulary tooling and its data, `requirements_llm/remote`, the GPU compose file, the `gpu-inference` / `vocab-drift` / `vocab-refresh` workflows, and their tests. All 76 are byte-identical at tag **`v1.0.0-beta`** (31534d5), so the release is where to take them from. Compared with keyword-extract's `test` (ufal/atrium-keyword-extract@dffe368):
  - **52 files are byte-identical** there already;
  - **14 differ:** `llm_utils.py` (~400 lines), `vocab_build.py`, `llm_run.py`, `requirements_llm.txt`, `docker-compose.gpu.yaml`, `vocab-drift.yml`, five vocabulary JSON/meta files, and three tests;
  - **10 are absent:** `llm_client_shared.py`, `openrouter_client.py`, `ollama_client.py`, `requirements_remote.txt`, and six tests.

  The per-file list is on ufal/atrium-keyword-extract#2.

**Why `v1.1.0-beta` and not `v1.0.0`:** `v1.0.0-beta` was already used, on 1 October, for the transitional snapshot that still carried the LLM API.

**Two steps for the maintainer, on GitHub, before tagging:**
1. **Mark `v1.0.0-beta` as a pre-release.**
   - It is this repository's only release, and a full one carrying the LLM `openapi.json`.
   - The release gate (and the push-time `openapi-compat` job, already red on `test` for this reason) compares the new spec with the highest non-pre-release. Removing `/extract_keywords*` at the same major version fails it.
   - Pre-releases never count as a baseline, so `v1.1.0-beta` then starts the digital spec fresh. Check it with `release.yml`'s `workflow_dispatch` dry run.
2. **GHCR:** the new `atrium-digital-convert-*` packages are private when created. Give `ufal/atrium-project` read access, so the hub's digital E2E can pull them.

**Remaining after the tag** (outside this repository):
- the hub E2E on the new `-api` image;
