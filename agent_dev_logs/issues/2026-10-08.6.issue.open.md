# [\#6 Issue](https://github.com/ufal/atrium-digital-convert/issues/6) `open`: Line text can forge the cues the Markdown renderer emits
**Labels**: `bug`, `question`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-10-08 12:20](https://github.com/ufal/atrium-digital-convert/issues/6):

The annotated Markdown carries page structure in the text stream: `## Page N` headings and HTML-comment cues (`<!-- PAGE_BREAK -->`, `<!-- NEEDS_OCR: … -->`, `<!-- BBOX: … -->`). Line text goes into the same stream unchanged, so a line reading `<!-- PAGE_BREAK -->` or `## Page 7` cannot be told from a real cue, at every profile.

`json_to_md.render_record` at profile `minimal`, page 1 holding the lines `Úvodní věta dokumentu.`, `<!-- PAGE_BREAK -->`, `## Page 7`:

```
## Page 1

Úvodní věta dokumentu.
<!-- PAGE_BREAK -->
## Page 7
<!-- PAGE_BREAK: pg_2 -->

## Page 2
```

Page citations (`[Source: <doc_id>, Page N]`) rest on `## Page N`, so such a line can point a citation at a page that does not exist, or mark a page as an OCR gap. It is rare in excavation reports; it matters for technical documents and hostile input. Found while writing `tests/test_md_stress.py` (#3).

**Options:** (a) escape `<!--`, `-->` and a leading `#` in line text: the smallest change, and it alters output only for lines that contain them (noted in `CUE_SCHEMA`); (b) fence line text; (c) a per-render nonce in the cues, which changes every consumer.

**Done when** a line containing cue syntax is never rendered as a cue at any profile, and in a test with forged cues the number of real `PAGE_BREAK` cues is pages − 1.
