## Context
#28 is the service AMČR's route step calls for every born-digital file; #10 §12 is its step-by-step plan, agreed with
David on 26 September. Three things changed since that plan was written, and this plan folds them in without
repeating it:
1. **The endpoint is `/reformat`** (the report's table after the meeting), not #10 W1's `POST /convert`. Nothing is
   published under either name yet, so the change is free.
2. **The repository becomes the converter** (#29). The service must not wait for the move: the report asks for a date
   earlier than the milestone. So `api-digital` is built **now, beside the LLM service**, and named by its destination
   from the first release, so the move changes none of its published identity.
3. **ocr-postprocess replaces alto-postprocess** (atrium-alto-postprocess#56). W3 (scoring) and W4 (the OCR merge)
   are that stage's work, and the shared module's hand-off rule names the program; the successor map (hub, *`doc-schema-v1`
   as the pilot baseline*) keeps the rule working under both names.

## Strategic actions

### A — W1: the service, named by its destination
1. **Image**: a Dockerfile target `api-digital` **FROM `digital`** — no LLM client, no torch. Published as
   `ghcr.io/ufal/atrium-llm-enrich-api-digital` until #29's rename, then under the new repository name (the only
   identity that moves).
2. **App**: `service/digital_api.py` on the vendored `service/atrium_service.py`, exactly as the other services use it:
   `build_info` (`/info`), `attach_health` (`/health`, `?deep=true`, `/ready`), `ServiceState` (the SIGTERM drain), the
   harmonised errors, `$PORT`/`HOST`, `GRACEFUL_SHUTDOWN_S`, `HEALTHCHECK`, `STOPSIGNAL` (#53, #55, #58).
3. **`POST /reformat`**: multipart `file`, optional `document_json` (the AMČR seed), optional `render=md`. Returns the
   record (validated), the Markdown when asked, and `paradata` as a `CreateAction` (#71 R2). Refusals: `ocr_text_layer`
   → 422; `unsupported` and `legacy_office_unsupported` (until W2) → 415 `unsupported_media_type` with the converter's
   `cause`; `encrypted`, `corrupt` → 422 with `cause`; `zip_limits_exceeded` → 413 `limit_exceeded`.
4. **Identity from day one**: its entry in `tests/openapi_contract_data.py` `SERVICES` carries
   `"service": "atrium-digital-born-convertor"` (the name agreed on #29), the spec is committed as
   `service/openapi-digital.json` and released as the asset `openapi-digital.json`. The release gate picks its baseline
   by asset name and treats a changed `x-atrium-service` as fatal (hub `atrium_openapi.py:238-283,417-420`); naming the
   service by its destination now means neither the rename nor the LLM service's departure ever trips it.
5. **Limits**: upload size, pages, file size and reader timeout from the environment, in `/info` (#53).
6. **Seed** (#71 R1): the seed wins for `doc_id`, file name and media type; the service holds the bytes, so it
   **checks `source.sha512`** against them and refuses a mismatch (a new registered code, `source_digest_mismatch`,
   422 — to register in the hub with the schema round).
7. **CI**: `build-targets` adds `api-digital`; `probe-targets` `["api", "api-digital"]`; the hub's `docker-tool` probes
   and `api-contract` apply unchanged. *Done when* (David's): the service image passes the same probe as `api`.

### B — W2: every born-digital type
1. **ODT, RTF, XLSX, ODS**: ocr-postprocess's readers (`text_formats.py:495-542`), **vendored with SHA pins** (the
   pattern of `tests/test_vendored_teitok_parity.py`), not copied and forked (atrium-alto-postprocess#56 §D).
2. **DOC, XLS**: LibreOffice headless in the `api-digital` image (`soffice --headless --convert-to docx|xlsx`,
   MPL-2.0), a conditional component in `para_config.txt`; `source` keeps the original name and media type, the paradata
   records the conversion.
3. **Shape**: paginated formats keep `bbox` and `pages[].canvas`; flow formats take pages from explicit breaks;
   spreadsheets give one page per sheet, one line per non-empty row, the sheet as a `tables[]` entry.
4. *Done when* (David's): each listed type yields a record with lines.

### C — W6 carried into the service
The refusal exists and is registered; the service returns it as 422 with `reason: ocr_text_layer`, and AMČR re-OCRs
those documents. One service-level test over the pinned fixture (`ocr_layer.pdf`).

### D — W4 and W3: with ocr-postprocess
1. **W4, the merge**: AMČR's ATR service OCRs the `needs_ocr` pages and returns ALTO for those pages only;
   ocr-postprocess merges them into the record this service started (by `page_index`/label), writing lines for those
   pages only. The contract and the fixture are here; the code is ocr-postprocess's. *Done when*: a PDF with scanned
   pages yields one record with both kinds of pages.
2. **W3, the score**: an additive rule in the shared module lets the line scorer write `lines[].categ` and
   `quality_score` (not the plane) on a born-digital record. The rule names the program through the successor map, so
   it holds for `alto-postprocess` and `ocr-postprocess` alike. Then quality means the same for every document, and
   #73's summary is computed over one scale.

### E — W5: TEITOK from the record's line positions
nlp-enrich takes layout from ALTO or flexiconv TEITOK only; a new layout source from `lines[].bbox` and
`pages[].canvas` is its work (`teitok_conformance_plan.md`). This repository provides the fixture records. *Done when*:
a born-digital PDF gets a TEITOK file with boxes.

### F — After the move (#29)
The identity strings of the repository change; `api-digital`'s do not. The service file may then become
`service/api.py` (the LLM service is gone), with the spec path updated in `SERVICES` — the asset name and the service
id stay.

## Verification / done-criteria
Mapped onto the issue's acceptance criteria:
1. *Born-digital documents enter the same chain as scanned ones*: the seeded digital E2E runs `api-digital` → page
   classification → ocr-postprocess (score) → nlp-enrich → keyword-extractor on a PDF, a DOCX, an ODT and an XLSX, and
   every record validates.
2. *Unusable text layers get a registered reason*: `ocr_text_layer` over the pinned fixture; no refusal without a
   `reason` or `cause`.
3. *OCR-required pages are handed off*: a fixture with image-only pages carries `needs_ocr` on exactly those pages;
   the W4 merge test.
4. *Quality and NLP on the shared record*: after W3, born-digital lines carry ocr-postprocess's `categ`.
5. *Deployable like the others*: the hub probes pass on `api-digital` (default port, `PORT=9000`, `HOST=127.0.0.1`,
   healthy, SIGTERM drain).

## Out of scope
