# Plan: Issue #28 - Implement `api-digital` service

## Objectives
* Transition the `digital-convert` CLI utility into a compliant synchronous REST service named `api-digital`.
* Support extended born-digital formats and implement strict text-layer validation and OCR routing flags.
* Enforce the project's OpenAPI contracts, error handling, and `atrium_document` v1.0 schema.
* Perform repository cleanup for licenses and experimental code.

## Execution Steps

* **Step 1: API Scaffolding & Contracts**
  * Bootstrap the `api-digital` service endpoint.
  * Define typed request, response, and error models conforming to the frozen `atrium_document` 1.0 schema.
  * Implement the standard `/info` health contract endpoint to expose service limits driven by environment variables.
* **Step 2: Core Conversion & Format Support**
  * Wrap the existing `digital-convert` logic into the new service.
  * Ensure full support for PDF, DOCX, ODT, RTF, XLSX, and ODS files, integrating the LibreOffice converter for DOC and XLS files.
* **Step 3: Text Layer Validation & OCR Routing**
  * Integrate the shared document reader and text-layer check (aligned with `alto-postprocess`). Apply the standard line-quality model.
  * Implement logic to flag pages without a usable text layer for OCR fallback.
  * Implement a guardrail to reject untrusted embedded OCR text layers in PDFs, returning the designated registered reason code for the orchestrator.
* **Step 4: TEITOK Construction**
  * Add logic to generate TEITOK output directly from native line positions for files lacking ALTO XML.
* **Step 5: Cleanup & Deployment Hygiene**
  * Update license declarations to relabel TEATER and AMČR vocabularies as CC0.
  * Remove experimental research code from the release line and production images.
  * Generate and commit the updated `openapi.json` file for the automated trust gate review.

## Validation
* Confirm the `/info` endpoint correctly reports environmental limits.
* Test all supported formats (PDF, DOCX, ODT, RTF, XLSX, ODS, DOC, XLS) to ensure valid `atrium_document` 1.0 output.
* Verify that image-only pages are successfully flagged for OCR and that embedded PDF OCR layers trigger the correct refusal reason code.
* Ensure TEITOK is correctly built from line positions.
* Verify `openapi.json` is accurate and research code is absent from the build.
