## Context

AMČR asked for born-digital documents to enter the same `atrium_document` chain as scans: one service, the common contract, every born-digital type, a shared reader and quality model, the OCR hand-off into the same record, and TEITOK from record geometry. The converter itself has existed since llm-enrich 0.8.0. What is missing is the service, the seed handshake, the formats beyond PDF/DOCX, and a clean repository identity, since this repository still ships the old LLM keyword service.

The maintainer added one capability on 2026-10-04: a per-page assessment that calls page-classification and ocr-postprocess and says, for each page:

* whether its text can be taken as it is, and if not, what kind of page it is;
* whether the text reads as language;
* which route it should take next: NLP, OCR/ATR, HTR, or nothing.

Those services are not deployed together yet, so the calls must degrade safely. This is kept apart from `/reformat`, so that the agreement with AMČR ("the converter calls no other stage; Temporal chains them") stays true for the production route.

## Design

### Two endpoints

|                      | `POST /reformat`                                                                                               | `POST /describe`                                                                                                                                        |
|----------------------|----------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| Purpose              | the production converter the AMČR route calls                                                                  | conversion + per-page assessment (sandbox, triage, demos)                                                                                               |
| Calls other services | **never**                                                                                                      | page-classification and ocr-postprocess, **only when configured**                                                                                       |
| Form fields          | `file`; optional `document_json` (seed or baseline); `markdown` (bool); `docx_page_breaks`                     | the same (no `markdown`); `stages` (CSV of stage names, default all configured, `none` for none); `classify_pages` (`needs_ocr`, the default, or `all`) |
| Returns              | `service`, `doc_id`, `document_json`, `markdown?`, `document_json_schema_error?`, `limits_applied`, `paradata` | the same, plus `pages[]` (per-page report), `summary`, `stages[]`                                                                                       |
| Refusals             | 413/415/422/429/501/503 with registered reasons                                                                | the same; a stage failure is **not** a refusal, it is a `stages[]` entry                                                                                |

### The record stays contract-clean

The record is still accreted only by owners:

* the converter writes `source`, `pages`/`lines`/`content`/`tables`;
* page-classification writes `page_categories` and `pages[].category/category_confidence`;
* ocr-postprocess writes `lines[].categ/quality_score/lang` and `pages[].quality_score/quality_band` (scoring only).

`/describe` passes the current record to each stage and adopts the returned record only after a guard:

* the same `doc_id` and `source`;
* the converter's own fields (`text`, `bbox`, `group_id`, `style`, `needs_ocr`, `needs_ocr_reason`, `canvas`, `page_index`) unchanged;
* no page or line row the converter did not write.

A failed guard keeps the previous record and reports the stage as `rejected` with its reason. The stage's answer still informs the report.

### The per-page report

The fields are listed in the digest. The route rules use `atrium_vocab.COLLECTIONS`, so the category taxonomy is not hard-coded twice. When no quality model ran, the quality falls back to the converter's decode check, labelled `source: digital-convert`.

### Stage clients (`service/stages.py`)

* Configuration: `PAGE_CLASSIFICATION_URL`, `OCR_POSTPROCESS_URL`, `STAGE_TIMEOUT_S`, `PAGE_CLASSIFICATION_VERSION`, `PAGE_CLASSIFICATION_TOPN`.
* Status values:

  | Status           | When                                                        |
  |------------------|-------------------------------------------------------------|
  | `not_configured` | the stage's URL is unset                                    |
  | `not_requested`  | the request excluded the stage                              |
  | `skipped`        | nothing to do (no PDF; no page needs classifying; no lines) |
  | `unavailable`    | connection error, timeout, 5xx/503                          |
  | `error`          | an unexpected 4xx or payload                                |
  | `rejected`       | the guard refused the returned record                       |
  | `partial`        | some pages failed                                           |
  | `ok`             | the stage ran                                               |

* `requests` runs in a worker thread. Nothing raises past the client. The first connection failure stops further calls to that stage.
* **page-classification:** `POST /predict_document` with the PDF, the record and `pages=<page_index list>`. Older servers that ignore `pages` still work: their predictions are filtered to the requested pages and used for the report, and the guard refuses their physically keyed record write.
* **ocr-postprocess:** `POST /score_record` with the record. On 404/405 from an older server it falls back to one `POST /process` (`task_type=text`) per page: report only, mapped line by line when the counts agree.
* `tools/stage_stub.py` serves both APIs deterministically for local runs and compose (`--profile stub`).

### Formats

| Input               | Reader                                                                                                         | `source.origin`                                |
|---------------------|----------------------------------------------------------------------------------------------------------------|------------------------------------------------|
| PDF                 | `digital_pdf` (pdfplumber + pypdfium2)                                                                         | `digital-born-pdf`                             |
| DOCX                | `digital_docx` (python-docx + lxml)                                                                            | `digital-born-docx`                            |
| ODT, ODS, XLSX, RTF | ocr-postprocess `text_formats.py`, vendored byte-identical, SHA-pinned                                         | `digital-born-odt` / `-ods` / `-xlsx` / `-rtf` |
| DOC, XLS            | headless LibreOffice → DOCX/XLSX, then the readers above; the original's name, media type and digests are kept | `digital-born-doc` / `-xls`                    |
| PPTX, ODP, EPUB, …  | refused, 415 `unsupported_media_type`                                                                          | —                                              |

Spreadsheets give one page per sheet and one line per row. `tables[]` for spreadsheets is a follow-up, not part of this round.

### Settings (`tool_limits.py`, reported in `/info`)

| Setting                                                                  | Default            | Over it                                 |
|--------------------------------------------------------------------------|--------------------|-----------------------------------------|
| `MAX_UPLOAD_MB`                                                          | 50                 | 413 `limit_exceeded`                    |
| `MAX_PAGES`                                                              | 2000               | 422 `limit_exceeded`                    |
| `MAX_CONCURRENT_JOBS`                                                    | 2                  | 429 `busy` with `Retry-After`           |
| `LIBREOFFICE_TIMEOUT_S`                                                  | 120                | 422 `limit_exceeded`                    |
| `STAGE_TIMEOUT_S`                                                        | 120                | the stage is `unavailable`              |
| `OCR_LAYER_DOCUMENT_SHARE`                                               | 0.5                | policy: whole-document `ocr_text_layer` |
| `ROUTE_TRASH_SHARE`                                                      | 0.5                | policy: route `ocr` on a digital page   |
| `ATRIUM_TEXT_INGEST_ODF_REPEAT_CAP`, `ATRIUM_TEXT_INGEST_PDF_OBJECT_CAP` | as ocr-postprocess | the vendored reader's own caps          |

### Reason codes

* Registered and reused: `unsupported_media_type` 415, `invalid_record` 422, `ocr_text_layer` 422, `limit_exceeded` 413/422, `busy` 429.
* New: **`source_digest_mismatch` 422.** It is registered at service import with `REASON_CODES.setdefault()`, so the vendored `atrium_service.py` stays byte-identical. The hub is asked to add it to the canonical registry, after which the local registration becomes a no-op and is removed.
* Readers' finer causes travel in `cause`: `encrypted`, `corrupt`, `zip_limits_exceeded`, `dependency_missing` (501), `legacy_office_unsupported`.

## Strategic actions

### A — Converter core
1. `sha512_file()`. In `prepare()`, compare the baseline's `source.sha512` with the original bytes before anything is parsed. A mismatch raises `DigitalInputError("source_digest_mismatch")`: CLI exit 3, HTTP 422. Covered by tests for a match, a mismatch, a seed without `sha512`, and DOC/XLS (checked before conversion).
2. `OCR_LAYER_DOCUMENT_SHARE` is read from `tool_limits`.
3. `sniff()` is extended:
   * OLE2 stream names separate DOC (`WordDocument`) from XLS (`Workbook`/`Book`);
   * ZIP packages that are not Word are delegated to `text_formats.sniff_kind`;
   * RTF is recognised by `{\rtf`.
4. `api_util/digital_text.py` (vendored reader → `DigitalDocument`) and `api_util/digital_legacy.py` (LibreOffice with a private profile and a timeout; a missing binary → `dependency_missing`).
5. `text_formats.py` vendored at the repo root (its isolated worker imports `tool_limits`), pinned by `tests/test_vendored_reader_parity.py`.

**Done when** every listed type yields a valid record with lines, and the existing PDF/DOCX golden tests are unchanged.

### B — Per-page report (`api_util/digital_report.py`)
Pure functions over the IR, the record and the stage answers; unit-tested route rules.

**Done when** the route of every fixture page is pinned by a test.

### C — Stage clients and stub (`service/stages.py`, `tools/stage_stub.py`)
**Done when** `/describe` returns 200 with the right `stages[]` status for: not configured, a stub, a stage down, a timeout, a 500, an old page-classification and an old ocr-postprocess.

### D — The service (`service/api.py`)
* Rewritten on the shared helpers: `/info`, `/health` (deep: converter dependencies and schema), `/ready`, SIGTERM drain, CORS, `paradata` (`atrium_rocrate.create_action`, program `digital-convert`), `attach_openapi_contract(app, "atrium-digital-convert", previous="atrium-llm-enrich")`.
* The spec is regenerated with `python atrium_openapi.py export --app service.api:app --out service/openapi.json`.

**Done when** the contract tests validate real responses against the published spec, and `atrium_openapi.py check` is clean.

### E — Repository identity, build and the LLM removal (with #1)
* `Dockerfile`: `remote`/`llm` go; `digital` gains LibreOffice; `api` is `FROM digital`.
* `docker.yml`, `security.yml`, `production-image.json`, `para_config.txt` (`program = digital-convert`, `v1.1.0-beta`), `CITATION.cff`, compose (`api`, `cli`, `stub`), `.env.example`.
* The LLM/vocabulary modules, data, requirements, workflows and tests are deleted, with a transfer manifest to keyword-extract.

**Done when** no first-party file names `atrium-llm-enrich` except as history, and the image-closure manifest matches the new entrypoint.

### F — Adjacent stages (this round, separate repositories)
1. **page-classification:**
   * `pages` subset on `/predict_document`;
   * page keys mapped to the record's labels through `page_index` when a baseline is sent;
   * `page_label` in each page entry.

   All additive. Proposed `v1.10.0-beta`.
2. **ocr-postprocess:**
   * `POST /score_record` (W3) scores a record's lines and writes only the scoring fields, never over a `Garbage`/`Inverted` line;
   * `document_hook.write_scores()` is the one sanctioned exception to its foreign-origin guard.

   Proposed `v1.9.0-beta`.
3. **The hub's shared module (the agreed "additive rule"):** an `ocr-postprocess` merge limited to the scoring fields on a `digital-born-*` record is a co-contribution, not an origination. It is added to the canonical `atrium_document.py` and `test_document_originators.py` and re-vendored into all repositories. The schema JSON is untouched, so no service spec changes.

### G — Documentation and logs
* `README.md` and `service/README.md` rewritten for the stage; `CONTRIBUTING.md`; `DEVLOG.md`.
* The #1/#4 logs refreshed. Issue comments drafted (#2, #1, #4, hub #71, keyword-extract#2) and two new-issue bodies (page-classification, ocr-postprocess).

## Done criteria for #2

* `/reformat`, `/describe`, `/health`, `/ready` and `/info` follow the common conventions; the spec carries the final identity.
* The seed's identity survives, and a wrong `sha512` is a stable 422 `source_digest_mismatch`.
* PDF, DOCX, ODT, RTF, XLSX and ODS work; DOC and XLS work through LibreOffice with provenance kept.
* Clean pages pass. Corrupt or empty pages carry `needs_ocr`. The `ocr_text_layer` policy is the documented setting.
* `/describe` gives every page a text-layer verdict, a category where classified, a quality verdict and a route, and keeps working with any subset of the stages down.
* Records come back from the stages with each block written by its owner only.
* The production image contains the digital stack and no LLM code.
* Still to be closed outside this round (and outside this issue's code): the ocr-postprocess subset merge (W4), nlp-enrich TEITOK from geometry (W5), and the seeded six-stage E2E in the hub.

## Out of scope

* OCR itself; the merge of ATR output (W4, Temporal route).
* TEITOK from record geometry (W5, nlp-enrich).
* Complex-layout engines in the production image (W7; Docling stays opt-in and local).
* Record-only mode (deferred under the pilot baseline).
* Keyword extraction and translation.
