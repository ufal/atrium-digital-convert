## Context

AMČR asked for born-digital documents to enter the same `atrium_document` chain as scans:
- one service with the common contract;
- every born-digital type;
- a shared reader and quality model;
- the OCR hand-off into the same record;
- TEITOK from record geometry.

The design was frozen on 2026-10-04 and shipped the next day:
- **`/reformat`**, the pure converter of the AMČR route;
- **`/describe`**, conversion plus a per-page assessment by page-classification and ocr-postprocess;
- the eight-format matrix;
- the seed handshake;
- the LLM code removed (#1).

The hub's shared-module round of the same day then turned two of this issue's proposals into the shared contract: `pages[].text_layer` and `source_digest_mismatch`. `v1.1.1-beta` consumes them.

## Design (as shipped)

### Two endpoints

|                      | `POST /reformat`                                                                                               | `POST /describe`                                                                                                                                        |
|----------------------|----------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| Purpose              | the production converter the AMČR route calls                                                                  | conversion + per-page assessment (sandbox, triage, demos)                                                                                               |
| Calls other services | **never**                                                                                                      | page-classification and ocr-postprocess, **only when configured**                                                                                       |
| Form fields          | `file`; optional `document_json` (seed or baseline); `markdown` (bool); `docx_page_breaks`                     | the same (no `markdown`); `stages` (CSV of stage names, default all configured, `none` for none); `classify_pages` (`needs_ocr`, the default, or `all`); `include_text` |
| Returns              | `service`, `doc_id`, `reader`, `document_json`, `markdown?`, `document_json_schema_error?`, `limits_applied`, `paradata` | the same, plus `pages[]` (per-page report), `summary`, `stages[]`                                                                                       |
| Refusals             | 413/415/422/429/501/503 with registered reasons                                                                | the same; a stage failure is **not** a refusal, it is a `stages[]` entry                                                                                |

### The record stays contract-clean

Only owners accrete the record:
* the converter writes `source`, `pages` (with `text_layer` since `v1.1.1-beta`), `lines`, `content` and `tables`;
* page-classification writes `page_categories` and `pages[].category/category_confidence`;
* ocr-postprocess writes either:
  * through `/score_record`: `lines[].categ/quality_score/lang` and `pages[].quality_score/quality_band` on existing rows (stamp `contribution: "scoring"`); or
  * on the Temporal route, through `/process` with `page=`: it replaces a flagged page's whole `lines` rows and sets that page's `quality_score`, `quality_band` and `ocr` (stamp `contribution: "ocr-handoff"`, flagged pages only).

`/describe` adopts a stage's returned record only past a guard:
- same `doc_id` and `source`;
- the converter's fields (`text`, `bbox`, `group_id`, `style`, `needs_ocr`, `needs_ocr_reason`, `canvas`, `page_index`, `text_layer`) unchanged;
- no new rows.

### Per-page report, stage clients, route rules

These are unchanged from the 2026-10-04 design and are documented in the README and `service/README.md`:
- stage status values `not_configured` / `not_requested` / `skipped` / `unavailable` / `error` / `rejected` / `partial` / `ok`;
- route rules over `atrium_vocab.COLLECTIONS`, with `ROUTE_TRASH_SHARE`;
- `tools/stage_stub.py` for local runs (compose profile `stub`).

### Formats

| Input               | Reader                                                                 | `source.origin`                                |
|---------------------|------------------------------------------------------------------------|------------------------------------------------|
| PDF                 | `digital_pdf` (pdfplumber + pypdfium2)                                 | `digital-born-pdf`                             |
| DOCX                | `digital_docx` (python-docx + lxml)                                    | `digital-born-docx`                            |
| ODT, ODS, XLSX, RTF | ocr-postprocess `text_formats.py`, vendored byte-identical, SHA-pinned | `digital-born-odt` / `-ods` / `-xlsx` / `-rtf` |
| DOC, XLS            | headless LibreOffice → DOCX/XLSX, then the readers above               | `digital-born-doc` / `-xls`                    |
| PPTX, ODP, EPUB, …  | refused, 415 `unsupported_media_type`                                  | —                                              |

### Settings (`tool_limits.py`, reported in `/info`)

`MAX_UPLOAD_MB` 50 · `MAX_PAGES` 2000 · `MAX_CONCURRENT_JOBS` 2 · `LIBREOFFICE_TIMEOUT_S` 120 · `STAGE_TIMEOUT_S` 120 · `OCR_LAYER_DOCUMENT_SHARE` 0.5 · `ROUTE_TRASH_SHARE` 0.5 · `ATRIUM_TEXT_INGEST_ODF_REPEAT_CAP`, `ATRIUM_TEXT_INGEST_PDF_OBJECT_CAP` (as in ocr-postprocess).

### Reason codes

All six come from the canonical registry vendored as `service/atrium_service.py`:
- `limit_exceeded`, `busy`, `unsupported_media_type`, `invalid_record`, `ocr_text_layer`;
- **`source_digest_mismatch`**, added canonically in hub `e8b1335`. The runtime registration of `v1.1.0-beta` was removed in `v1.1.1-beta`.

The readers' finer causes travel in `cause`: `encrypted`, `corrupt`, `zip_limits_exceeded`, `dependency_missing` (501), `legacy_office_unsupported`, `conversion_failed`.
