## Context

The annotated Markdown puts page structure and document text in one stream, and line text goes into it unchanged. A line that reads `<!-- PAGE_BREAK -->` or `## Page 7` is a cue to every reader. Reproduced on `a5a1e38` at all three profiles: two `PAGE_BREAK` lines and three `## Page` lines for a two-page record.

keyword-extract's whole-document prompt reads exactly these markers to place a line on a page, and builds `[Source: <doc_id>, Page N]` from the answer. The fix escapes the cue syntax in text where text enters the renderer, so ordinary documents render byte-identically and no consumer changes.

## Execution plan

### Phase A — one escape, applied where raw text enters a row
1. `api_util/layout_md.py`: `escape_text(text: str) -> str`. It changes only what could be read as structure:
   - `<!--` → `&lt;!--` and `-->` → `--&gt;`, anywhere in the text;
   - a leading run of `#` (after optional spaces) → `\#`, so `## Page 7` renders as the literal text `## Page 7` and is not a heading;
   - nothing else: emphasis, `|` and HTML are left alone (the stress suite holds tables and `<u>` cues to their current form).
2. Apply it at the three entry points:
   - `json_to_md.py:173` (the record's `lines[].text`), before `_decorate()` adds `#`/`**`;
   - the cells passed to `L.md_table()` (`json_to_md.py:343`);
   - the TEITOK/ALTO readers in `xml_to_md.py` (`_read_alto_rows`, `:60`; `_read_teitok_layout`, `:221`), where a row's text is first read.

   `rows_to_layout_markdown()` itself stays as it is, because it also writes the record route's intended markup.
3. The deprecated `docx_to_md.py` / `pdf_to_md.py` (`--legacy`, PDF `--ocr`) get the same helper where they write a paragraph's text, so the escape does not depend on the route.
4. `layout_md.py`'s module docstring and `CUE_SCHEMA` documentation, plus README's "The format" bullet (`README.md:333-336`): document text never contains a raw `<!--`, `-->` or line-leading `#`; a consumer that sees one is reading a cue.

### Phase B — tests (`tests/test_md_stress.py`)
5. A record built with `make_record()` plus a page whose lines are the forgeries: `<!-- PAGE_BREAK -->`, `<!-- PAGE_BREAK: pg_9 -->`, `<!-- NEEDS_OCR: pg_1 (x) -->`, `<!-- BBOX: [1, 2, 3, 4] -->`, `## Page 7`, `### Heading`, `# Title`, and `a --> b <!-- c` mid-line. For every profile (`PROFILES`), on both routes:
   - `PAGE_BREAK` lines = pages − 1 and `## Page` lines = pages;
   - `cue_names()` is unchanged by the forgeries;
   - `text_stream()` still contains each forged line's words.
6. The existing suite passes unchanged: ordinary text is byte-identical. That is the regression guard for "only these lines change".

### Phase C — the consumer
7. keyword-extract needs no change for (a): its prompt keys on the real markers, which can no longer be forged. A line in its DEVLOG and in #2's thread notes that the renderer escapes, so a reviewer does not add a second defence there.
