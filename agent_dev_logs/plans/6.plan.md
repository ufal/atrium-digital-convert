## Context

The annotated Markdown carries page structure and document text in one stream, and line text went into it unchanged. A line reading `<!-- PAGE_BREAK -->` or `## Page 7` was a cue to every reader. keyword-extract's whole-document prompt places a line on a page by exactly these markers, and builds `[Source: <doc_id>, Page N]` from the answer.

The fix escapes cue syntax wherever document text enters the Markdown. Ordinary documents render byte-identically, and no consumer changes.

The 10-14 refresh widened 10-08's plan in two ways:
- **More sources.**
  - A PDF's own page labels reach `## Page {label}` and `PAGE_BREAK: {label}`.
  - Reasons, font names and watermarks reach cue bodies.
- **The escapes move.**
  - The ALTO reader 10-08 named also feeds `--format text`, so the escape belongs to the layout readers and the Markdown writers.
  - Table cells are built from rows, so the leading-`#` escape comes after the tables are assembled.

## Execution plan

### Phase A — the helpers ✅
1. **`api_util/layout_md.py`:**
   - **`escape_cue_delimiters`**: `<!--` → `&lt;!--`, `-->` → `--&gt;`.
   - **`escape_line_start`**: a leading `#` → `\#`.
   - **`escape_text`**: both.
   - **`cue_value`**: the line breaks `str.splitlines` knows become spaces, then the delimiter escape.
   - **Where they apply:**
     - `_comment()` passes every body through `cue_value`;
     - `_escape_cell`, `footnote_def` and `image` escape the delimiters only, since a cell never starts a line.
   - **Documented** in the module docstring.

### Phase B — where text enters ✅
2. **Record route (`json_to_md.py`):**
   - delimiters are escaped where a line becomes a row;
   - in `_assemble_regions`, after `_assemble_tables`, body rows (except the table block) and header/footer rows get `escape_line_start` before `_decorate()` adds the intended `#` marks;
   - the `content.text` fallback is escaped line by line, and its title goes through `cue_value`.
3. **TEITOK/ALTO route (`xml_to_md.py`):**
   - `_read_teitok_layout` and `_read_alto_layout` return escaped rows (`_as_markdown_text`);
   - `rows_to_markdown` escapes its text;
   - `rows_to_layout_markdown` and `rows_to_markdown` write `## Page`/title values through `cue_value`;
   - `rows_to_plain_text` and the rows readers stay raw.
4. **The deprecated renderers:**
   - `docx_to_md`: run text (the delimiters, so the FONT/STYLE cues around runs stay), the paragraph's leading `#`, header/footer text, the title;
   - `pdf_to_md`: block and OCR-block text, the title.
5. **README:** "Text never forges a cue", in "Record → annotated Markdown".

### Phase C — tests ✅
6. **`tests/test_layout_md.py`:** the helpers; ordinary text unchanged; idempotence; cue values on one line; cells keep `#1`.
7. **`tests/test_md_stress.py`:**
   - forged lines in the body, the running header, a footnote and cells, on both routes at every profile:
     - `## Page` = pages, `PAGE_BREAK` = pages − 1, one `NEEDS_OCR`;
     - `cue_names()` as without forgeries;
     - the words kept;
   - the issue's reproduction;
   - a forged page label and `needs_ocr_reason`;
   - ALTO `layout`/`markdown` escaped, `text` raw.
8. **The deprecated renderers:** `tests/test_pdf_to_md.py` and `tests/test_docx_to_md.py`.

### Phase D — the consumer
9. keyword-extract needs no change: its prompt keys on markers that can no longer be forged. One line in its DEVLOG and in its #2 thread notes that the renderer escapes, so no second defence is added there.

## Out of scope

- Hostile input beyond cue forgery (prompt injection in document text): a property of every LLM consumer, not of the renderer.
- Markdown emphasis inside text (`_`, `*`): it garbles a word's look, not the page structure.
