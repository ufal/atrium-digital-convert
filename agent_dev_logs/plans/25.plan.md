## Strategic actions
### A — Licence first (external, cheap) — _narrowed 2026-09-26: the contact stays, for shared evaluation data_
Write to Jan Švec: licence (MIT/Apache-2.0), current state, interest in a joint evaluation (our harness and
archaeological gold pages against theirs), and the origin and licences of the Ollama model tags. Record the answer in
`para_config.txt` terms before anything is wrapped.

### B — Wrap, don't import — ⛔ not planned
Behind the existing seam: `pdf_to_md.py --ocr-engine {tesseract,archivatorium}` calling its CLI in a subprocess
(its Python 3.12 requirement and `PyPDF2`/`pdf2image` stay out of our environment), with the `NEEDS_OCR` fallback
unchanged on failure and model, mode and sampling parameters written to paradata. No new entry point.

### C — Score, then decide — ⛔ not planned
`bench_compare.py` on the same pages: Tesseract `ces` against all four modes, CER/WER per quality tier, plus an
on/off ablation of previous-page context. Report the table to hub #22 and decide adopt / benchmark-only / drop.

### D — If adopted: where the text goes — ⛔ not planned
A VLM transcription is OCR output: its record origin must be a `vlm:…` value, which `ORIGIN_ORIGINATORS` hands to
alto-postprocess, and it has no boxes — so it fills `content`/`lines[].text` but never `bbox`, and a TEITOK file made
from it has no facsimile. Say so wherever the engine is offered.
