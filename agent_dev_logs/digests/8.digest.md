## 🧭 Where it stands — 2026-11-06

### What the issue asks

- **What is missing:** `/describe` gives each page a text-layer verdict, page-classification's label (top 3), a
  quality score, the layout counts and a route. It does not say what kind of document the page is.
- **The answer:** a decision model reads the rendered page and its text, and returns a type with a probability for
  each option, at two levels:
  - a group of 6: text, photograph, aerial photograph, plan or map, drawing, unspecified;
  - a type of 32, from AMČR's heslář `dokument_typ`. It has 41 terms with `api.aiscr.cz` URIs; the 9 data-only ones
    are left out. `neurčený dokument` abstains.
- **The list is generated,** not written by hand, from keyword-extract's `data_samples/vocab/amcr_flat.json`, with
  its source commit and SHA-256.
- **The stage:** an opt-in `document-type` stage, beside `page-classification` and `ocr-postprocess`.
  - It is chosen through `--stages` / `stages`, with the same status set as the other stages.
  - The CLI and the service give the same output.
  - The default stage set and every existing report stay as they are.
- **Report fields only:** `PageReport.document_type` and `summary.document_type`. The record has no field for a type,
  and `pages[].category` belongs to page-classification.

### The evaluation

| Data                           | Pages | Gold                                                                           | Where                |
|--------------------------------|------:|--------------------------------------------------------------------------------|----------------------|
| The 15 AMČR PDFs (#5)          | 2,514 | the catalogue type of each PDF (document level); 300 annotated pages, 50 twice | cluster, counts only |
| `tests/fixtures/digital/` PDFs |     — | none (wiring and latency only)                                                 | anywhere             |

Page-classification's labels for the 2,514 pages: `PHOTO` 798, `LINE_P` 608, `DRAW` 482, `TEXT_P` 436, `DRAW_L` 176,
the rest 14. The 300 pages are stratified by these labels, with every page of the rare ones.

**The runs** compare:
- text only, image only, and both;
- flat against two-level;
- the models: Clef, then Clef-Flash; Strands Decider 2B on text only.

**The metrics:**
- accuracy and macro-F1 per level, and the confusion matrix by group;
- Brier and ECE;
- latency, with text and image requests measured apart;
- `invalid` answers and timeouts.

## ⚠️ Limits

- **No record field** until two things happen:
  - a `document-type` scheme is agreed with AMČR (`atrium_vocab.py` in the hub);
  - a field is granted in a hub issue of its own. #71 is closed.

  Both make a class (c) change in `docs/shared_components.md`.
- **`route_page()` does not change.** The type informs a person or a later rule; it does not route.
- **Inner pages of reports rarely show their type;** the title page does. The two levels let a page answer `text`
  with confidence and its exact type with little.
- **Rendered images exist only as `regenerable` recipes,** never as stored files.
- **Not in the pilot release.** The stage lands on `test` after the pilot set is approved (11-11).
- **No hosted inference on archive pages.**
