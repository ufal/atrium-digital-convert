## 🎯 Goal

Turn the repository into the single-purpose **born-digital conversion stage** of ATRIUM:

* born-digital input → `atrium_document` record;
* program id remains **`digital-convert`**;
* production HTTP surface is **`POST /reformat`** and returns the record, with Markdown only when requested;
* the repository and its production image no longer contain the old keyword/LLM service;
* the one remaining LLM/vocabulary implementation lives in `atrium-keyword-extract`, not in two copies;
* the service participates in the current six-stage production architecture and record/paradata contract.

The issue is no longer primarily a GitHub rename problem. The repository already exists under its final agreed name; the work is now the **functional and release migration from the transitional `llm-enrich` contents to the born-digital stage**.

| Page classification         | [`atrium-page-classification`](https://github.com/ufal/atrium-page-classification/tree/test) | Page-image routing / classification                          | Separate scanned-document stage; `digital-convert` does not call it internally.                               |

| **Born-digital conversion** | **[`atrium-digital-convert`](https://github.com/ufal/atrium-digital-convert/tree/test)**     | **Born-digital originator of `atrium_document`**             | **This issue.** Produces the digital pages/lines/tables and `needs_ocr` information.                          |
| NLP enrichment              | [`atrium-nlp-enrich`](https://github.com/ufal/atrium-nlp-enrich/tree/test)                   | LINDAT UDPipe/NameTag, TEITOK and record projection          | Consumes the record; keyword/LLM extraction is no longer its responsibility.                                  |
| Keyword extraction          | [`atrium-keyword-extract`](https://github.com/ufal/atrium-keyword-extract/tree/test)         | Statistical + controlled keyword stage                       | Receives the LLM/vocabulary implementation moved out of `digital-convert`; owns the future `keywords` block.  |

Two assumptions in the pre-split plan are therefore obsolete:

1. `llm-enrich` is **not** the final owner of the production API; `digital-convert` is.
2. keyword extraction is **not** part of this repository after the split; both keyword kinds belong to `keyword-extract`.

The hub's deployment map confirms that the intended production service image is one `-api` image per stage, while `atrium-digital-convert` currently has only the batch `...-digital` image and is the one remaining stage whose `api-digital` service is not yet built. See [`atrium-project/docs/k8s_deployment.md`](https://github.com/ufal/atrium-project/blob/test/docs/k8s_deployment.md#which-image-to-deploy--one-production-image-per-stage-72).

## ✅ What's settled

### Repository and naming

* The current repository name is **`ufal/atrium-digital-convert`**.
* Keep that repository and its ARUP-CAS fork as they are; do not create another successor.
* The old `atrium-llm-enrich` repository is historical. Its remaining README/archive handling belongs to the repository-transition work in #72.
* Program id in records remains **`digital-convert`**.

### Functional boundary

`digital-convert` owns the **born-digital originator** responsibilities:

* read the original file;
* build the born-digital `atrium_document` positional plane;
* check the embedded text layer;
* mark pages that need OCR;
* preserve source identity and record identity;
* optionally render the same record to Markdown.

It does **not**:

* run page classification as an internal service call;
* call OCR post-processing over HTTP itself;
* run UDPipe/NameTag;
* own statistical or controlled keywords;
* own the production LLM service;
* create a second quality model or a second record layout plane.

### API contract

The target service is **`POST /reformat`**. The current AMČR direction is:

* input file plus optional AMČR seed record;
* output the `atrium_document` record by default;
* Markdown only when explicitly requested;
* include the run `paradata` / Process Run Crate `CreateAction` like the other production services;
* preserve `doc_id`, `source.sha512`, file name and media type;
* validate the uploaded bytes against the seed digest and return `source_digest_mismatch` on mismatch;
* retain the registered `ocr_text_layer` refusal and page-level `needs_ocr` semantics.

The exact mixed-PDF `ocr_text_layer` threshold is still a **#2 API decision** and should not be silently fixed in #1.

### LLM/vocabulary ownership

The final architecture has **one keyword repository**. `atrium-keyword-extract` already contains the LLM/vocabulary implementation; the remaining duplicate in `digital-convert` must leave this tree. The production converter must not carry `torch`, LLM clients, vocabulary harvesting or controlled-keyword endpoints.
