## 🎯 Goal

A line of document text can never be read as a page heading or a cue, so the number of real `## Page N` sections equals the number of pages, and the number of real `PAGE_BREAK` cues is pages − 1, whatever the text holds. Ordinary text renders exactly as before.

## 🔎 What the code did

**Reproduced** on `a5a1e38` and again on `8fee29b`. `json_to_md.render_record()` at profile `minimal`, on a two-page record whose page 1 holds `Úvodní věta dokumentu.`, `<!-- PAGE_BREAK -->`, `## Page 7`:

```
## Page 1

Úvodní věta dokumentu.
<!-- PAGE_BREAK -->
## Page 7
<!-- PAGE_BREAK: pg_2 -->

## Page 2
```

That is two `PAGE_BREAK` cues for two pages, and a third page heading. The same at `standard` and `full`.

**Who reads the cues.** keyword-extract's whole-document clients (`atrium-keyword-extract/llm_client_shared.py`, `6efb40c`):
- **The prompt** places a line on the page whose `<!-- PAGE_BREAK: pg_N -->` or `## Page N` marker is above it (`:733`, `:834`).
- **The answer's page** becomes the citation `[Source: <doc_id>, Page N]` (`:1004`).

So a forged `## Page 7` gives a citation to page 7, and a forged `NEEDS_OCR` marks a page as an OCR gap. The line-by-line path (`kind=controlled` on the record) does not read Markdown.

## 🧪 The fix (`c3eb0df`)

**`api_util/layout_md.py`:**
- `escape_cue_delimiters` (`<!--` → `&lt;!--`, `-->` → `--&gt;`);
- `escape_line_start` (a leading `#` → `\#`);
- `escape_text` (both);
- `cue_value` (line breaks → spaces, plus the delimiters).

All are idempotent. `_comment()` passes every cue body through `cue_value`, and `_escape_cell`, `footnote_def` and `image` escape the delimiters.

**Where text enters the Markdown:**
- `json_to_md`:
  - delimiters are escaped where a line becomes a row (`:160`);
  - the leading `#` is escaped for body, header and footer rows in `_assemble_regions` (`:259`, `:285`), after the tables are assembled and before `_decorate()` adds the intended heading marks;
  - in the fallback, `content.text` line by line.
- `xml_to_md`:
  - the layout readers' rows (`_as_markdown_text`, `:201`) and `rows_to_markdown` (`:525`);
  - `rows_to_plain_text` stays raw;
  - page labels and titles go through `cue_value` (`:442`, `:455`, `:514`, `:521`).
- The deprecated `docx_to_md` (run text, paragraphs, headers) and `pdf_to_md` (blocks, OCR blocks, titles).

**Docs:** `layout_md`'s module docstring, `rows_to_layout_markdown`'s contract, and README's "Text never forges a cue".

**Tests** (18 new; each failed on the old code):
- `tests/test_layout_md.py`: the helpers, idempotence, cue values, cells;
- `tests/test_md_stress.py`, both routes at every profile:

  - a forged page label and `needs_ocr_reason`;
  - cells keep `#1`;
  - ALTO `layout`/`markdown` escaped, `text` raw;
- one test each for the deprecated DOCX and PDF renderers.
