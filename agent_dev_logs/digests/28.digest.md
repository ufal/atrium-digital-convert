# Digest: Issue #28 - Implement `api-digital` service for born-digital documents

## Context
The born-digital document path requires `digital-convert` to operate as a standalone service within the pipeline. 
Currently, in `llm-enrich` version 0.8.0, `digital-convert` exists only as a command-line utility inside the `-digital` 
image. Promoting this to a fully compliant `api-digital` service is the next required step for the Temporal orchestration.

## Core Problem & Requirements
To seamlessly integrate with the AMČR processing chain, `api-digital` must be created as a synchronous endpoint with the following capabilities:

* **Format Support**: The service must handle a widened range of born-digital types, including PDF, DOCX, ODT, RTF, XLSX, 
and ODS. Legacy DOC and XLS formats should be supported via a LibreOffice converter. 
* **Shared Logic**: It must utilize a document reader and text-layer check shared with `alto-postprocess`, alongside 
the same line-quality model used for OCR.
* **OCR Routing & Guardrails**: Pages lacking a usable text layer must be explicitly flagged so they can be handed 
off to the OCR service (with OCR lines subsequently merged into the same record). Conversely, any OCR text layer already
embedded inside a PDF must be treated as untrusted and rejected, emitting a specific registered reason code that the Temporal route step relies on.
* **TEITOK Generation**: The service must build TEITOK directly from the record's line positions when ALTO is not present,
ensuring born-digital PDFs receive the same TEITOK view as scanned documents.
* **Contract Adherence**: The API must read and write the frozen `atrium_document` 1.0 schema, implement typed 
request/response and error models, expose environment limits via an `/info` endpoint, and commit its `openapi.json` for release gate tracking.

## Secondary Cleanup Tasks
* **Licensing**: The AMČR vocabularies and TEATER within the repository must be explicitly relabeled to CC0 (from CC BY-NC 4.0).
* **Release Hygiene**: Experimental research code must be kept strictly off the release line and out of the production images.
