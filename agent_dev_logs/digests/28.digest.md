## 🎯 Goal
Promote the born-digital converter from a command line to the **production service `api-digital`**, the born-digital
branch of AMČR's route step. The issue's scope, condensed:
1. an independent service with the common health, `/info`, typed request/response and stable error contracts;
2. PDF, DOCX, ODT, RTF, XLSX and ODS; DOC and XLS through LibreOffice;
3. the shared document reader and text-layer check used by the born-digital and OCR paths;
4. pages without a usable text layer found and handed to OCR;
5. born-digital lines on the same downstream quality/NLP record path as OCR text;
6. TEITOK built from the record's line positions when there is no ALTO.

Acceptance, in full: born-digital documents enter the same `atrium_document` chain as scanned ones; an unsupported or
unusable text layer gets an explicit registered reason, never a silent pass; OCR-required pages are handed to the
ATR/OCR route; line quality and NLP work on the resulting shared record; `api-digital` deploys with the same operational
conventions as the other services.

## ✅ What's settled
- **Scope**: the six points above; **engine**: the light one only (Docling stays a local opt-in target, W7).
- **LibreOffice** for DOC and XLS (accepted by ÚFAL, report item 11).
- **`ocr_text_layer`** is the refusal the route step relies on; OCR text layers in PDFs are never trusted (report §5).
- **The service's name** after the meeting: `/reformat` (report §2.2).
- **The repository** becomes the born-digital converter (#29); the program id stays `digital-convert`.
