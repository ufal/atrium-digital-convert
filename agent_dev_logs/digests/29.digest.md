step of AMČR's pipeline. Everything else this repository holds today — the LLM engine, the controlled-vocabulary
keywords, the vocabulary build, the benchmarks — leaves for `ufal/atrium-keyword-extractor` (nlp-enrich#40), so the
repository and its images carry the converter only.

## ✅ What's settled
- **The born-digital path is one stage of its own** (report items 5 and 11), with the common health, error and limits
  contract, every born-digital type AMČR accepts, the OCR hand-off into the same record, TEITOK from line positions.
- **The record is the output.** The converter's program id is `digital-convert`, not the repository's name, so the
  move changes no record and no block grant.
- **The keyword and LLM code leaves** (nlp-enrich#40).
- **OCR stays outside** the ÚFAL repositories (report §5); a PDF whose text layer is an earlier OCR run is refused
  with `ocr_text_layer`.

## ⏳ Open
1. **Repository strategy**: rename this repository in place (the issue's wording) or extract the converter into a new
   one — see the plan, §A1.
2. **What `/reformat` returns**: the record only, or the record and its Markdown.
3. **"Calls to ocr-postprocess and page-classification"**: in the AMČR architecture Temporal chains the stages; the
   plan proposes no service-to-service calls (§A3).
4. **The name's spelling**, `convertor` (the issue) or `converter` (the code's word throughout), before the first
   image is published under it.
5. **Where the Markdown renderer lives**, since keyword-extractor's LLM path needs it too.
6. **Dates**: the report asks for an earlier date for the service than the milestone (30 April 2027).
