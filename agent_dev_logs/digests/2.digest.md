## 🎯 Goal

Turn the born-digital converter into the production service of the born-digital route:

* **`POST /reformat`** — a born-digital file (and optionally the AMČR seed) in, the `atrium_document` record out, Markdown only on request, run `paradata` as a Process Run Crate `CreateAction`. It calls no other service. This is the endpoint the AMČR route step (Temporal) uses.
* **`POST /describe`** — the same conversion, then a **per-page assessment**:
  * is the page's text layer extractable and trustworthy, and if not, what kind of page it is (page-classification);
  * is the extracted text readable (ocr-postprocess's quality model);
  * the route each page should take next: `nlp` (good to go), `ocr` (re-acquire with ATR), `htr` (handwriting) or `none` (no text to read);
  * the page's layout facts and its text.

  It calls the adjacent services only when their URLs are configured, and it degrades to a local assessment when they are not running.
* every born-digital type AMČR accepts: PDF, DOCX, ODT, RTF, XLSX, ODS, and DOC/XLS through LibreOffice;
* the common ATRIUM service contract: `/health`, `/ready`, `/info`, settings in `/info`, typed responses, registered reason codes, SIGTERM drain;
* the seed handshake: `doc_id`, `source.sha512`, file name and media type kept; a seed whose `sha512` does not match the bytes is refused with **`source_digest_mismatch`**.

## 🔬 Adjacent-service facts that shape `/describe`

- **page-classification `/predict_document`** takes the whole PDF only and classifies every page. With a `document_json` it accretes `page_categories` and `pages[].category/category_confidence` under its own stamp, but it **keys pages by physical number "1".."N"**, while digital-convert keys them by the PDF's **page label** (`/PageLabels`: "iv", "A-1"). On a labelled PDF its accretion would attach a category to the wrong row, or to a new one, without any error.

  Categories: `DRAW`, `DRAW_L`, `LINE_HW`, `LINE_P`, `LINE_T`, `PHOTO`, `PHOTO_L`, `TEXT`, `TEXT_HW`, `TEXT_P`, `TEXT_T`. `atrium_vocab.COLLECTIONS` groups them into handwritten / printed / typed / graphical / tabular, which is what a route hint needs.
- **ocr-postprocess `/process`** writes nothing into a `digital-born-*` record. `_accretion_records()` returns nothing for that origin, and `document_hook.write_document_block()` drops positional blocks for a foreign origin, so W3 is not implemented. Its `task_type=text` path classifies one line per non-blank input line, in order.
- **The shared module.** `lines[].categ` is granted to both originators with disjoint label sets: `Garbage`/`Inverted` (decode verdicts) versus `Clear`/`Noisy`/`Trash`/`Non-text`/`Empty`. A scorer that rewrote `categ` would erase the converter's decode verdict. `_assert_origin_consistent()` lets ocr-postprocess write into a digital-born record only after a `needs_ocr` hand-off, so a scoring-only write on a clean digital record would be reported as a mixed plane.
- **keyword-extract** lacks `llm_client_shared.py`, `openrouter_client.py` and `ollama_client.py`; its `llm_utils.py` differs from this repository's by about 400 lines and `vocab_build.py` by 43. The LLM copy here can leave only with a transfer manifest; the history stays reachable at tag `v1.0.0-beta` / commit `770ab3f`.

## ✅ Settled

- `POST /reformat` is the production endpoint the AMČR route calls. It returns the record (Markdown on request) and `paradata`, and **calls no other service**.
- `POST /describe` is an additional, optional endpoint for sandbox, demo and triage use. It is not a replacement for Temporal chaining, and AMČR's route does not have to use it.
- Service id `atrium-digital-convert` (rename declared from `atrium-llm-enrich` in the spec); images `ghcr.io/ufal/atrium-digital-convert-api` (production) and `…-digital` (CLI); one spec, `service/openapi.json`. The historical `atrium-digital-born-convertor` and `openapi-digital.json` are dropped.
- Program id in the record: `digital-convert` (unchanged).
- `source_digest_mismatch`: 422, checked against the **original** bytes before any parsing, also for DOC/XLS before conversion.
- `ocr_text_layer` answers both readings of motyc's question:
  - prior-OCR pages ≥ `OCR_LAYER_DOCUMENT_SHARE` (default 0.5) of the text-bearing pages → whole-document 422;
  - below it → a record with those pages flagged `needs_ocr` and a prior-OCR reason.

  The share becomes a declared setting reported in `/info`.
- The OCR merge of flagged pages is ocr-postprocess's (W4) under Temporal; neither endpoint does OCR.
- Line quality has one model and one label set (ocr-postprocess). The converter's decode verdicts (`Garbage`/`Inverted`) win over it on the lines that carry them.
- LibreOffice (MPL-2.0) in the `digital` image, for DOC/XLS only, declared conditionally.
- Keyword extraction and translation stay downstream; no LLM code remains in this repository's tree or images after this round.

## 🧩 The per-page report (`/describe`)

```text
pages[]:
  page, page_index
  text_layer        digital | garbled | ocr | none | blank
  needs_ocr, needs_ocr_reason
  category          {label, confidence, top[], source: page-classification} | null
  quality           {source: ocr-postprocess | digital-convert, score, band,
                     lines_by_category, lang} | null
  route             nlp | ocr | htr | none      route_reason
  layout            {canvas, lines, blocks, tables, headings, regions, columns,
                     images, vector_paths}
  text              the page's text in reading order
summary: pages, routes{nlp,ocr,htr,none}, needs_ocr_pages, document_route
stages[]: {stage, status, http_status, reason, detail, elapsed_s, service_version, paradata}
```

Route rules (deterministic, documented in the README):

* **A digital page** whose layer decodes → `nlp`. If ocr-postprocess calls more than `ROUTE_TRASH_SHARE` (0.5) of its scored lines `Trash` → `ocr`.
* **A `needs_ocr` page**, by page category:
  * handwritten only → `htr`;
  * printed, typed or tabular text → `ocr`;
  * `DRAW`/`PHOTO` only → `none`;
  * unknown (classifier not configured) → `ocr`.
* **A blank page** → `none`.

The record carries what each owner is allowed to write. The report is regenerable from the record plus the stage answers, so it is not stored.
