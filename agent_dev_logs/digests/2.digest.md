## 🎯 Goal

The production service of the born-digital route:

* **`POST /reformat`**: a born-digital file (and optionally the AMČR seed) in, the `atrium_document` record out, Markdown only on request, the run's `paradata` as a Process Run Crate `CreateAction`. It calls no other service. This is the endpoint the AMČR route step (Temporal) uses.
* **`POST /describe`** (optional): the same conversion, then a per-page assessment by page-classification and ocr-postprocess when their URLs are configured: text-layer verdict, page category, line quality, and the route `nlp` / `ocr` / `htr` / `none`. It degrades to a local assessment when they are not running.
* every born-digital type AMČR accepts: PDF, DOCX, ODT, RTF, XLSX, ODS, and DOC/XLS through LibreOffice;
* the common service contract: `/health`, `/ready`, `/info` (settings included), typed responses, registered reason codes, SIGTERM drain;
* the seed handshake: `doc_id`, `source.sha512`, file name and media type kept; a seed whose `sha512` does not match the bytes is refused with `source_digest_mismatch`.

## 🔬 Adjacent-service facts that shape the route

- **page-classification `v1.9.2-beta`:** `/predict_document` takes `pages` (1-based physical) and writes categories under the record's labels when the baseline rows carry `page_index`; each page entry carries `page_label` when the baseline has a row for that position. Its tag's Docker smoke went red at `PORT=9000` on a model warm-up timeout (run 37269822039), not on the new code; the images were promoted and the hub fixed the probe (`4cbf900`).
- **ocr-postprocess `v1.9.0-beta` / `v1.9.1-beta`:** `/score_record` writes only `SCORING_FIELDS` (stamp `contribution: "scoring"`). `/process` with `page=` merges an ATR ALTO page into a flagged page of this record: the page's `lines` rows are replaced through the hub's `replace_page_rows()`, its `pages[]` row gains `quality_score`, `quality_band` and `ocr.engine` (`HANDOFF_PAGE_FIELDS`), `source`, `content`, `tables` and every other page are left alone, and the stamps read `contribution: "ocr-handoff"`. Its DEVLOG lists `tests/test_ocr_handoff.py` (18 tests, the `/process` `page=` cases), but that file is not in the W4 commit `173c3a1`. On `test`, the hand-off is covered only by the shared-module tests (`test_document_originators.py`) and one older hook test.
- **Hub `e2e_assert.py`** (born-digital branch) accepts the scoring stamp and the `ocr-handoff` stamp on a flagged page only, and checks `needs_ocr` against `text_layer`.

## ✅ Settled

- `POST /reformat` is the production endpoint and calls no other service; `POST /describe` is optional (sandbox, demo, triage) and not part of the AMČR route.
- Service id `atrium-digital-convert`; images `ghcr.io/ufal/atrium-digital-convert-api` (production) and `-digital` (CLI); one spec, `service/openapi.json`. Program id in the record: `digital-convert`.
- `source_digest_mismatch` (422) is canonical in every service's registry.
- `ocr_text_layer` follows `OCR_LAYER_DOCUMENT_SHARE`; the per-page `text_layer` enum is in the schema, so the route step reads a value instead of the prose of `needs_ocr_reason`.
- The OCR merge of flagged pages is ocr-postprocess's (W4), per page, under Temporal.
- One line-quality model (ocr-postprocess); the converter's `Garbage`/`Inverted` verdicts stand.
- No LLM code in this repository or its images.
