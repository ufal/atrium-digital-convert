- The upload is held whole in memory (`service/api.py:595`, `read_upload_bounded`).

**The stages' own limits, which `/describe` meets first on these files.** Read on 10-09; this is new since the 10-08 comment:

| Stage (`tool_limits.py`)                                                       | Default        | With these files                                                                                 |
|--------------------------------------------------------------------------------|----------------|--------------------------------------------------------------------------------------------------|
| page-classification `MAX_UPLOAD_MB` (`:19`)                                    | 10 MB per part | 11 of the 15 PDFs are larger. The record `/describe` sends is a second part                      |
| page-classification `MAX_PDF_PAGES` (`:24`)                                    | 50 pages       | counts the pages classified: every flagged page by default, every page with `classify_pages=all` |
| page-classification `MAX_IMAGE_PIXELS` (`:35`) at `PDF_RENDER_DPI` 300 (`:30`) | 178,956,970 px | a page larger than about 1.25 × A0 fails the **whole** call (a large plan sheet)                 |
| ocr-postprocess `MAX_UPLOAD_MB` (`:33`)                                        | 25 MB          | the record part of `/score_record`; a large text-heavy record can exceed it                      |

- A 413 from a stage is a 4xx that is neither 404/405 nor 429. `/describe` reports it as the stage's `error` (`service/stages.py:225-227`), not `unavailable`; the request still answers 200, but that document has no categories or quality.
- In the AMČR deployment Temporal calls the stages itself. The same values decide there, so the pilot limits are four services' settings, not one.

**What is flagged** (`api_util/digital_pdf.py:562-581`, per page):

| Verdict   | When                                                                                       | Flag                                                                                              |
|-----------|--------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| `none`    | no words at all, whatever is drawn                                                         | `needs_ocr`; the reason names what the page draws (images, vector paths) or that it draws nothing |
| `ocr`     | invisible text (render mode 3) is ≥ `OCR_LAYER_MIN_RATIO` (0.5) of the page's text objects | `needs_ocr`, prior-OCR reason                                                                     |
| `garbled` | lines that do not decode (`decode_sanity`, `digital_to_json.py:559-572`)                   | `needs_ocr`                                                                                       |
| `digital` | anything else with at least one word                                                       | not flagged                                                                                       |

A PDF whose text-bearing pages are mostly prior-OCR (`OCR_LAYER_DOCUMENT_SHARE`, 0.5) is refused whole: CLI exit 3, HTTP 422 `ocr_text_layer`. Such a document gets no record; it belongs to the OCR route. Scanned AMČR documents with a searchable layer would end here.

**The gap.** A page with a little real, visible text over a full-page image is `digital` and not flagged: a scan with a stamp, a running header, or text added from the PDF's metadata.
- The adapter counts the page's images (`:562`) and vector paths (`:563`), but the verdict does not use them, and it does not measure how much of the page the images cover.
- `/describe` does not catch it either. page-classification is asked by default only about the flagged pages (`service/api.py:859`). A `digital` page goes to OCR only when ocr-postprocess calls more than `ROUTE_TRASH_SHARE` (0.5) of its lines `Trash`, and a clean stamp has no `Trash` lines.

## 🧪 Experiments prepared (2026-10-09)

One cluster job, `issue5_samples_job.sh`, runs every stage over the folder on one node; it is cluster-side and not tracked. `tools/samples_report.py` (tracked, tested) measures the run and writes `report/`.

| Stage                 | What runs                                                                                              | Settles                                                                            |
|-----------------------|--------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------|
| `02_inventory`        | size, pages, digest, producer, largest page at 300 dpi                                                 | the limits the job sets; the pages over page-classification's pixel cap            |
| `10_cli_light`        | the CLI per PDF: exit code, time, peak memory                                                          | ask 1 without HTTP; the verdicts and `ocr_text_layer` refusals on real files       |
| `11_cli_negative`     | `MAX_PAGES=1`; a broken PDF; a non-PDF; seeds with a wrong and a right digest                          | the refusals and exit codes                                                        |
| `20_cli_docling`      | `--engine docling` (on a GPU node)                                                                     | light against Docling: lines, tables, headings, furniture, time, memory            |
| `30_markdown`         | `json_to_md.py` at all three profiles; `scripts/detail_budget.py`                                      | `NEEDS_OCR` cues = flagged pages; the token cost per profile                       |
| `40_service_contract` | the largest file at the default limit (413) and at the pilot one (200); 429 with one slot; seed digest | ask 1 over HTTP                                                                    |
| `41_reformat`         | `/reformat markdown=true`, a fresh server per PDF: time, the server's peak memory                      | the memory budget; CLI and service give the same record                            |
| `50_describe_none`    | `/describe stages=none`                                                                                | the converter-only routes (ask 2 as the pilot would see it)                        |
| `61_describe_stages`  | page-classification and ocr-postprocess served on the node, limits raised to the files                 | stage times (→ `STAGE_TIMEOUT_S`), quality bands, routes                           |
| `62_describe_all`     | `classify_pages=all`                                                                                   | a category for every page, the input to the gap's measurement                      |
| `70_report`           | `summary.md`/`.csv`, `page_signals.csv`, `candidates.md` + thumbnails, `limits.md`, `deliver/`         | the per-document table, the gap measured, the pilot limits, the files to hand back |

- **The gap's signals**, per page: image coverage (the union of image-object boxes over the crop box, Form XObjects included), body and header/footer characters, text-area share, category, route.
- **The rule measured:** a `digital` page with coverage ≥ 0.85 and at most 200 body characters is a candidate. A grid over coverage {0.5, 0.7, 0.85, 0.95} × characters {0, 50, 200, 500, 1000} shows what other thresholds would catch.
- **GPU and CPU.**
  - With a GPU, Docling runs, and page-classification asks the five-model ensemble.
  - On a CPU-only node, Docling is off (`DOCLING=on` forces it), and page-classification asks `v4.4` alone.
  - Both kinds of node run every other stage the same way.
- **Dry run** in this session with `STAGES=stub`, on the generated fixtures, `digital_born/sample.pdf`, a stamp-over-scan page and a 53.6 MB synthetic scan:
  - every stage passes, and every contract check passes (413, 200 at the raised limit, 429 with `Retry-After`, both seed checks, an unknown stage);
  - the stamp page and the synthetic scan are the only candidates;
  - a re-submit resumes;
  - `FORCE` reruns one stage, and a wrong path exits 2 before anything runs.
- **Not covered by the dry run:** the real page-classification and ocr-postprocess (torch and model downloads); only the stub stood in for them.

## 🔑 Decisions open

1. **Pilot limits**, AMČR's call, from the run's `limits.md`. Four services' settings:
   - digital-convert: `MAX_UPLOAD_MB` (at least 160 for these files), `MAX_PAGES`, `STAGE_TIMEOUT_S`;
   - page-classification: `MAX_UPLOAD_MB`, `MAX_PDF_PAGES`, `MAX_IMAGE_PIXELS`;
   - ocr-postprocess: `MAX_UPLOAD_MB`.
2. **How a "little text over a page image" page is marked.** The schema ties `needs_ocr` to `garbled`/`ocr`/`none`, so marking a `digital` page needs one of:
   - (i) a new `text_layer` value: a hub schema change, all six repositories revendored;
   - (ii) `/describe`'s report routing it to `ocr` with a reason, the record unchanged;
   - (iii) calling it `none`, which is not true of its text.

   Recommended: (ii) first; (i) only if AMČR needs the mark in the stored record. The run's numbers decide the thresholds.
3. **Sharing.** The records, reports and thumbnails are AMČR material: on the public issue, or by filesender only?
