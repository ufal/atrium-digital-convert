## 🔎 What is established (`a5a1e38`; the 10-08 comment)

**Size and time limits** (`tool_limits.py`, all in `/info` and `service/README.md`'s Limits table):

| Limit                                          | Default | Over it                                                                                                                  |
|------------------------------------------------|---------|--------------------------------------------------------------------------------------------------------------------------|
| `MAX_UPLOAD_MB` (`upload_limit(50)`, `:24-26`) | 50 MB   | 413 `limit_exceeded`, naming the setting                                                                                 |
| `MAX_PAGES` (`:28-31`)                         | 2000    | 422 `limit_exceeded` ("split the document")                                                                              |
| `LIBREOFFICE_TIMEOUT_S` (`:39-41`)             | 120 s   | 422 (office formats only)                                                                                                |
| `STAGE_TIMEOUT_S` (`:43-45`)                   | 120 s   | `/describe` only: the stage (page-classification, ocr-postprocess) is reported `unavailable`; the request still succeeds |
| `MAX_CONCURRENT_JOBS` (`:35`)                  | 2       | 429 `busy`                                                                                                               |

- The upload is read whole into memory (`service/api.py:595`, `read_upload_bounded`).
- Measured on 10-08 with `MAX_UPLOAD_MB=200` (`/reformat`, a synthetic 120 MB PDF): accepted in 4 s; the server's peak resident memory rose by about 250 MB. So budget about twice the largest file per concurrent job.
- Which values the pilot should run with was asked on the thread and is not answered yet.

**What is flagged** (`api_util/digital_pdf.py:556-581`, per page):

| Verdict   | When                                                                                       | Flag                                                                                          |
|-----------|--------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| `none`    | no words at all, whatever is drawn                                                         | `needs_ocr`, reason names what the page draws (images, vector paths) or that it draws nothing |
| `ocr`     | invisible text (render mode 3) is ≥ `OCR_LAYER_MIN_RATIO` (0.5) of the page's text objects | `needs_ocr`, prior-OCR reason                                                                 |
| `garbled` | lines that do not decode (`decode_sanity`, `digital_to_json.py:559-572`)                   | `needs_ocr`                                                                                   |
| `digital` | anything else with at least one word                                                       | not flagged                                                                                   |

`pages[].text_layer` carries the verdict. The schema closes the enum (`digital`, `garbled`, `ocr`, `none`, `blank`) and says `garbled`, `ocr` and `none` are exactly the `needs_ocr` pages.

**The gap.** A page with a little real, visible text over a full-page image is `digital` and not flagged: a scan with a stamp, a running header, or only text that came from the PDF's metadata.
- The adapter records the page's image count (`current.images = len(page.images)`, `:562`) and vector paths (`:563`), but the verdict does not use them.
- `/describe` does not catch it either. page-classification is asked by default only about "the pages without a usable text layer" (`service/stages.py`, module docstring). The route rule sends a `digital` page to OCR only when ocr-postprocess calls more than `ROUTE_TRASH_SHARE` (0.5) of its lines `Trash` (`tool_limits.py:56-59`). A clean stamp has no `Trash` lines.

## 🔑 Decisions open

1. **Pilot limits:** `MAX_UPLOAD_MB` (at least the largest of the 15 files), `STAGE_TIMEOUT_S` (page-classification on a 500-page scan takes longer than 120 s), `MAX_PAGES`. AMČR's call; the run below gives the numbers to decide with.
2. **How a "little text over a page image" page is marked.** The schema ties `needs_ocr` to `garbled`/`ocr`/`none`, so marking a `digital` page needs one of:
   - (i) a new `text_layer` value: a hub schema change, all six repositories revendored;
   - (ii) `/describe`'s report routing it to `ocr` with a reason, the record unchanged;
   - (iii) calling it `none`, which is not true of its text.

   Recommended: (ii) first; (i) only if AMČR needs the mark in the stored record.
